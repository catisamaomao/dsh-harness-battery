## 测试与 CI

独立复跑的本地离线检查通过：14 项 Node 测试、10 项发布扫描测试、20 项运行器测试和 9 项 POSIX 进程身份测试；默认跳过 3 项需显式启用的已安装 DSH mock 验收。运行器增加了默认文件编码为 cp1252 时的中文目录 / 计划读写，以及非 UTF-8 标准输出环境下的直接 CLI 回归。Windows 明确跳过不适用的 POSIX 进程信号测试。

跨平台审查已推动以下修正：Git 文本采用 LF、图片按二进制保存，避免 Windows 换行改变冻结摘要；POSIX 权限位断言不用于 Windows；符号链接测试在缺少创建权限时明确跳过相关 fixture，目录链接采用对应平台支持的形式。真实 Windows CI 暴露的文本编码问题通过运行器显式 UTF-8 文件读写、CLI 管道输出、宿主子进程环境和测试调用链修复；证据 manifest 统一使用正斜杠相对路径，保留读取端的路径安全校验。模拟平台分支不等于在真实 Windows / Linux runner 上完成执行，最终三系统 CI 结果仍需单独确认。

发布集成者已确认提交 `b4b0b0d` 的 GitHub Actions 在 macOS、Ubuntu 和 Windows 三系统全部通过。这验证了编码与路径修正；该提交尚不包含随后完成的 PID 身份修正，后者仍需在最终提交上另验云端 CI。

## 进程清理问题复核

原实现仅登记短命 worker 的 PID，题末清理可能指向被复用的进程编号。现实现由宿主读取内核启动身份和 UID，核验登记进程属于当前 DSH 根进程的后代；信号发送前复核身份，已退出的组长不会凭历史数字触发 `killpg`。对工具启动器使用受控 shell 包装，在启动和退出阶段暂停，宿主核验身份并记录后代后恢复，保留已验证的后台工具清理场景。身份变化及未核验登记的跳过计数写入运行元数据。

独立静态复核和 9 项回归覆盖非后代登记、异 UID、根进程及 worker PID 复用、退出组长、信号前复核、已回收 Popen PID 和控制帧不构成权限。运行器维护者另行复跑了实际已安装 DSH 的 3 项 mock：任务与独立 grader / 报告、工具取消、正常结束后的后台工具清理，均通过；这些 mock 不调用真实模型、不读取凭据或用户记忆。

该修正闭合了此次审查指出的“仅凭旧 PID / 组编号清理”缺陷。它没有提供原子的进程身份校验与发信号操作，也不证明能收束任意恶意自守护进程。清理结论限于上述 DSH 工具场景；系统调用之间仍有竞态边界，未知身份按保守规则跳过。最终发布仍须确认相同源码的三系统 CI、打包扫描和本机安装验收，不把部分静态检查当作完整安全证明。
